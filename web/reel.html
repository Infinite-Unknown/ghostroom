The problem

A timetable knows what is booked.
It does not know who showed up.

1 · Booked

The class is on the timetable. Nobody comes.

The room still counts as taken for the whole slot.

2 · Cooling nothing

The aircon runs anyway.

A 2-hour no-show is about 7 kWh on an empty room. That is a model: 3.5 kW per room.

3 · Turned away

A student is told the room is taken.

APSpace’s classroom finder reads the timetable only.

How it is built

Cloud, IoT and network meet in one Google Sheet.

IoT · simulated

In each room

  • Motion sensor
  • Aircon relay: Eco Mode or on
  • ESP32 firmware sketch

Network

The network is a sensor

  • Wi-Fi device counts (simulated)
  • HTTPS and JSON, both ways
  • No heartbeat for 15 min = offline

Cloud

One Sheet, one script, one site

  • Google Sheet: the contract
  • Apps Script: engine, triggers, email
  • Vercel site, Gemini API chat

Sensors always win

What is real, what is simulated

The timetable is real. The sensors are simulated. We say which is which.

Real

  • APU’s public timetable feed
  • 60 rooms, 3,201 class sessions
  • The rules engine and unattended runs
  • The chat, answering from live rows

Simulated

  • Who is in a room
  • The aircon relay
  • Energy and RM figures: a model
  • The no-show rate: assumed, not measured
